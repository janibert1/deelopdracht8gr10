Code Organiseren & Samenwerken

Om goed te kunnen programmeren in groepsverband is een plan en verdeling van taken noodzakelijk. Een goede manier om dit te doen is door de code in classes, methoden, en functies op te delen, en hier een class diagram en flowchart van te maken. De class diagram documenteert de structuur van de objecten en methoden die deze objecten kunnen uitvoeren. De flowchart hoeft alleen gemaakt te worden van de hoofdfunctie. De flowchart beeld uit in welke volgorde verschillende functies en methoden aangeroepen worden. Om compleet te zijn wordt aangeraden om in de flowchart in ieder geval aan te geven:

  • De naam van de functie
  • De volgorde van de input argumenten, naam, en datatype (class, float, integer, list)
  • De volgorde van de return waarden, naam, datatype (class, float, integer, list)

Op deze manier kun je in een groep afspreken hoe bepaalde functies gaat noemen en wat de input en output wordt van deze functies. Zie hier een voorbeeld van een flowchart en een class diagram om een html pagina te maken die de locaties van een schip plot:

De flowchart is in eerste instantie misschien nog niet 100% correct (veranderingen tijdens het programmeren mogen). Zorg dat je flowchart up to date blijft en dat je de veranderingen bekend zijn in je groep.

Flowcharts en class diagrammen kan je maken in PowerPoint, Microsoft Visio, paint, of ieder ander willekeurige online tool. Sla ze op als pdf of als afbeelding (jpeg, png). Referentie voor UML class diagrams. Referentie voor flowchart symbols en blokken.

Naamgeving conventies

Om python bestanden overzichtelijk en leesbaar te houden raden we aan om variabelen, functies, constanten, classes, bestanden en errors logische namen te geven, niet te veel gebruik te maken van ongebruikelijke afkortingen, zelfbeschrijvende code te schrijven, en de volgende naamgeving conventies te gebruiken:

Item Conventie Voorbeeld
variablen snake_case ship_length
functies camelCase() calculateStability()
classes PascalCase ContainerShip
constanten ALL_CAPS WATER_DENSITY
python bestanden snake_case.py read_files.py
exceptions PascalCase StabilityCalculationError

Hoofdfunctie en file verdeling

Naast de naamgeving moet je een hoofdfunctie bedenken waarin je samen afspreekt in welke volgorde je de andere functies gaat aanroepen (onthoud dat een functie wordt pas uitgevoerd wanneer de functie aangeroepen wordt). Verdeel de functies en classes over verschillende python files met een logische verdeling van taken die in deze files gedaan worden. Een voorbeeld van een taak verdeling per python file zou kunnen zijn:

  • De hoofdfunctie (main.py hier start en eindigt het programma), 
  • Input (read_files.py hier zit bijvoorbeeld de functie readTankVolumes() in die de tank volume csv bestanden leest)
  • Output (generate_output.py hier plot je bijvoorbeeld de krachtverdeling en vul je het antwoordenblad.json)
  • Scheep classe (ship.py hier definieer je de Ship classe waarin ook methoden staan voor bijvoorbeeld evenwichtBerekening())

Zorg in ieder python bestand dat de benodigde python functies geïmporteerd worden. Wil je de readTankVolumes() functie in main.py gebruiken? Zet dan bovenin de main.py file: from read_files import readTankVolumes. Vervolgens kan je de readTankVolumes functie gebruiken in de main python file.

Wil je de evenwichtBerekening() methode uit de Ship classe in main.py gebruiken? Zet dan bovenin de main.py file: from schip import Ship. Vervolgens kan je de Ship classe initialiseren as bijvoorbeeld ship1, en met schip1.evenwichtsBerekening() de evenwichtsberekening aanroepen.

Functie richtlijnen

Algemene richtlijnen voor functies zijn: 

  • Zorg er voor dat iedere functie een logische naam heeft,
  • Zorg er voor dat iedere functie een docstring heeft,
  • Gebruik #commentaar bij gebruik moeilijk te interpreteren regels code,
  • Voorkom gebruik van globale variabelen in functies (als je een variabele in de functie gebruikt geef hem dan mee als argument), 
  • Zorg dat een functie op één scherm past (dus niet meer dan +/-30 regels per functie, niet breder dan je code editor, anders probeer je waarschijnlijk te veel te doen in een functie)
  • Print statements in functies zijn ongebruikelijk (kan uiteraard tijdelijk als je wat wilt debuggen).
  • Maak nooit twee functies of methoden die exact het zelfde doen.
  • Functies kunnen elkaar aanroepen. Hiet alles hoeft vanuit de main aangeroepen te worden.
